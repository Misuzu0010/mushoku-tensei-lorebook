# 00-04 全流水线工作流深度总结与设计哲学（Workflow Architecture & Methodology）

本指南系统性总结了将大型长篇叙事作品（长篇小说、轻小说、网文、动漫剧本）转化为**面向大语言模型（LLM）的角色扮演（RP）、故事推演（Storytelling）与沉浸式对话代理（AI Agent）**的工业级流水线标准。

---

## 一、为什么传统角色扮演与世界书方案往往会失败？

在传统方案中，通常直接将整本小说灌给大模型，或提取一份静态的维基式词条库。这种做法在复杂长篇作品中必然引发三大灾难性缺陷：

1. **时空错乱与超前剧透（Timeline Bleeding & Spoilers）**：
   - 传统世界书是“单一静态条目”，例如把角色“后期失去手臂”、“习得终极魔术”、“亲人战死”、“迎娶伴侣”直接写在人物词条里。当玩家希望扮演该角色幼年或前期剧情时，模型会莫名其妙地说出后期剧情，瞬间出戏。
2. **脸谱化与严重的 OOC（Character Distortion & Out-of-Character）**：
   - 很多角色的外在言谈与内心真实想法存在巨大张力（如：鲁迪表面卑微温和，内心大叔吐槽与创伤防卫；克莱恩表面克制沉稳，内心疯狂腹诽）。简单塞入性格标签（如“温柔、坚毅”）会导致模型输出沦为千篇一律的 AI 客套腔。
3. **上下文窗口浪费与信息稀释（Context Bloating）**：
   - 将未经提炼的原著长篇段落作为知识库灌入，不仅费用高昂、响应迟缓，而且会导致模型注意力涣散，无法精准命中核心设定。

## 二、00-04 工作流的五大核心创新

本套流水线通过五个严密衔接的阶段，彻底解决了上述三大痛点：

```
[原始图书] ── 00 ──> [章节切片] ── 01 ──> [设定草稿] ── 02 ──> [分阶段世界书]
                          │
                          └────── 03 ──> [角色语料] ── 04 ──> [分阶段角色卡]
```

### 1. 时空分阶段切片（Stage Slicing）
- **核心逻辑**：将整个长篇作品的时间跨度解构为“1 个跨阶段通用底座（`shared_world`）+ N 个历史阶段（`stage{N}`）”。
- **动态隔离**：同一角色、地点或势力，在不同时期拆解为完全不同的条目，只描述该时期客观呈现的状态。RP 推演时，按当前剧情仅挂载对应阶段的文件，在物理层彻底阻断跨阶段剧透。

### 2. 客观世界事实与主观认知的严格剥离（Grounding & Cognitive Discrepancy）
- 在 01 提取阶段，强制区分：
  - **客观事实（Ground Truth）**：世界运行的真实规律。
  - **主观认知（Subjective Perception）**：角色当下所听信的谎言、神话或偏见。
- 涉及重大反转时，采用**双条目机制**（第一条记录表象，第二条记录真相并附带 `reveal_arc` 启用条件）。

### 3. 表里言行双轨驱动协议（Dual-Layer Protocol）
- 在 03 与 04 阶段，明确区分：
  - **外在台词（Spoken Dialogue）**：脱口而出的真实话语，用 `「……」` 呈现，严格遵守当期的礼仪、声纹与口头禅。
  - **内心独白（Inner Monologue）**：脑内真实心理博弈，用 `（心声：……）` 呈现，展现深层恐惧、本能欲望与自嘲。

### 4. 50~150 汉字高信息密度硬约束（Information Density Rule）
- 世界书每个条目的 `content` 强制要求在 **50~150 汉字**之间。
- 坚决剔除抒情与无关描写，保留纯粹的机制、事实、人际与弱点，实现对大模型 Context Window 的极致利用。

### 5. 标准化 Few-Shot `<START>` 对话语料库（Voiceprint Modeling）
- 角色卡不靠抽象形容词堆砌，而是从 03 挖掘的真实语料中提炼出涵盖“日常”、“战斗”、“恋爱”、“暴怒”、“创伤”等不同情境的多轮标准对话示例，让大模型通过 In-Context Learning 达到最高仿生度。

## 三、各阶段任务一览表

| 阶段编号 | 规约文件名 | 核心输入 | 核心产物 | 关键控制点 |
|:---:|:---|:---|:---|:---|
| **00** | `00_tool_create.md` | EPUB / TXT 原书 | `outputs/chapters/{vol}/{ch}.md` | 遵循 Spine 阅读顺序；清洗注音/垃圾标签；智能过滤扉页与插图；保留原著标点与引号。 |
| **01** | `01_world_extract.md` | 章节正文 `.md` | `outputs/world_raw/{vol}/{ch}.md` | 逐字附原文依据；严禁脑补推测；九大维度覆盖；标定主观偏见与反转线索。 |
| **02** | `02_world_merge.md` | `world_raw/` 草稿 | `world_stages/*.json` | 实施 Stage 划分；50~150 汉字硬核校验；触发词穷举；双条目防剧透隔离；生成 `world_summary.md` 索引。 |
| **03** | `03_character_data.md` | 章节正文 `.md` | `outputs/char_raw/{char}/*.md` | 5层穿透无标注说话人识别；外在台词与脑内心声严格分流；微习惯与关系矩阵提取。 |
| **04** | `04_character_card.md` | `char_raw/` + 世界书 | `character_cards/{char}/` | 分阶段状态切片；表里双轨系统指令；至少 6 组 `<START>` Few-Shot；导出 Tavern V2 JSON 与 Markdown。 |

## 四、版权合规与公开仓库安全规范

为了在公开平台（如 GitHub）开源世界书与工具链时彻底规避版权风险，工作流制定了严格的**数据分层隔离机制**：

```
[本地隔离区 · Git 忽略]
├── inputs/               <-- 原始 EPUB 二进制图书（绝不上云）
└── outputs/              <-- 包含小说完整原文切片与带长篇引用的草稿（绝不上云）
    ├── chapters/
    ├── world_raw/
    └── char_raw/

[开源交付区 · Git 跟踪]
├── world_stages/         <-- 100% 提炼后的原创结构化知识库（合理使用/事实摘要，无侵权风险）
├── character_cards/      <-- 基于语料提炼的原创角色人格卡（Tavern V2）
├── prompt/               <-- 自动化提示词规范与通用模板
└── tools/                <-- 自动化构建与清洗脚本引擎
```
